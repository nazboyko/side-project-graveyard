# Visual asset contracts

No artwork was generated in this task. Status `REQUIRED` means **ASSET REQUIRED**: the source must be supplied and visually approved before its integration. Dimensions below describe proposed source masters; smaller responsive derivatives are build output, not additional generation requests. All filenames are repository-relative.

The minimum set is five source images. It deliberately avoids a nine-stone/thirteen-relic library, a CMS schema change and a new image dependency. Source masters may be PNG; delivery should be compressed AVIF/WebP with alpha where appropriate. Validate actual Astro encoder output before committing a format strategy. All byte budgets below are compressed transfer estimates, not measured assets.

## Shared generation and review contract

Use one material/light description for the entire set: handmade physical cemetery miniature at last light; muted limestone, olive grass and dark soil; diffuse cool upper-left sky light; faint warm distant horizon; tactile fine surfaces; restrained photographic realism; no glossy fantasy rendering.

Do not generate project text, names, dates, inscriptions, UI, controls, logos, watermarks or gibberish engraving. Do not add people, skulls, pumpkins, bats, ghosts, dramatic moon, glowing eyes, cathedral spectacle, technology symbols or humorous props. Text and humor come from the application. Reject assets whose camera, light or scale cannot match the existing HTML objects.

Approve each source at actual desktop/mobile placement size, not only as an attractive standalone image. Check a dark/light alpha background, compare it with the rest of the set, and record tool/prompt/candidates/rejections honestly in the build log when generation is authorized. No fake temporary artwork or SVG scenery substitute.

## Minimum asset set for implementation

Approve **A01 environment-wide, A02 environment-mobile, A03 limestone-tile, A04 ground-tile and A05 terrain-edge**. Five source images, no dynamic text. Phase 0 checks all five as one coherent set; Phase 1 integrates only the environment/ground. P01–P03, a cutout library, dedicated fog texture, unique detail backdrop and refreshed social card are optional and must not block that first pass.

Estimated selected decorative transfer using these five sources: desktop approximately 450–600 KB, mobile approximately 280–400 KB, plus existing fonts/site files. This leaves substantial room below the approximately 2 MB initial high-impact target without requiring heavy WebGL or twenty-seven unique object images.

## Approved clarification: A01 establishes the asset set

A01 `environment-wide` establishes the definitive visual language for the complete generated set. The existing five-source minimum remains unchanged, but its preparation is sequential:

1. Generate A01 candidates.
2. Obtain visual approval of A01 as the anchor, including its memorable static first-viewport composition and protected HTML safe zones.
3. Generate A02–A05 using that approved A01 image as the visual reference.
4. Review the complete set together for consistency at intended desktop/mobile scale.

A02–A05 must inherit A01's lighting direction, color temperature, realism level, material scale, atmospheric softness, camera impression and contrast level. Record which approved A01 version each source references. Their individual format, viewpoint and material-tile constraints still apply. Do not generate all five independently and reconcile them afterward. A materially revised anchor requires checking its dependent assets again before accepting the set.

This is a future Phase 0 sequence. Approval of this specification does not authorize starting image generation or application implementation.
